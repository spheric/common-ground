# data/tvfy — They Vote For You integration

Voting-record data from [They Vote For You](https://theyvoteforyou.org.au) (OpenAustralia
Foundation), joined onto Common Ground issues so each one can show how Labor, the Coalition, the
Greens, and One Nation actually voted in Parliament — not just what they say.

Files:

- **`mapping.json`** — hand-verified input, **not generated**. Maps Common Ground `issue.id`s to
  one or more TVFY policy ids, each with a `polarity` (does agreeing with the policy count as
  "supports" (`1`) or "opposes" (`-1`) the issue's `question`?), a `strength`
  (`"direct"` | `"related"`), and a short `note`. Someone has to read the TVFY policy description
  and the Common Ground question and decide these by hand — get it wrong and the voting record
  will look like it says the opposite of what it does. Shape:

  ```json
  {
    "meta": { "...": "..." },
    "issues": {
      "<issue_id>": [
        { "policy_id": 3, "polarity": 1, "strength": "direct", "note": "..." }
      ]
    }
  }
  ```

- **`divisions.json`** — generated by `node scripts/tvfy/fetch-divisions.mjs`. Fetches every
  parliamentary division referenced by a mapped policy and tallies each division's votes into the
  four-party set (plus `other`), using every member's party AS RECORDED AT THE TIME of that
  division — not their current party. Also keeps a trimmed per-member roll
  (`member_votes: [{person_id, party, vote}]`) per division, which `fetch.mjs` needs (see below).
  Safe to regenerate at any time; never hand-edited.

- **`records.json`** — generated by `node scripts/tvfy/fetch.mjs`. Fetches each mapped policy id
  (or every TVFY policy with `--all`) from the TVFY API and aggregates per-member agreement scores
  into per-party figures (members / voted / for / against / mixed / median & mean agreement),
  joined against the current federal Parliament (`/people.json`) only — former members are
  ignored. Safe to regenerate at any time; never hand-edited. **Requires `divisions.json` to
  already exist** — `fetch.mjs` reads it to run the party-switcher exclusion below, and exits with
  a clear error if it's missing, so `fetch-divisions.mjs` must be run first.

  Party-switcher exclusion: TVFY's `people_comparisons` attribute a member's *entire* division
  history on a policy to their *current* party, so a member who has since crossed the floor to
  another party has their pre-switch votes silently folded into their new party's aggregate.
  `fetch.mjs` cross-references each current member's votes on a policy (via `divisions.json`'s
  `member_votes`) against their current party; if any of those votes were cast under a party that
  `classifyParty` maps to a *different* bucket than their current one (or to no bucket at all),
  that member is excluded from `voted`/`for`/`against`/`mixed`/the medians for that policy and
  counted instead in that party's `excluded_switchers`. They're still counted in `members` (the
  current headcount). Historical party strings that classify to the *same* bucket as the current
  one (e.g. Liberal → Liberal National Party) are not a switch.

- Running `node scripts/tvfy/apply.mjs` reads `mapping.json` + `records.json` +
  `divisions.json` and writes an `issue.voting` block onto every mapped issue in
  `data/dataset.json` (and removes `voting` from any issue no longer mapped). Idempotent —
  re-running with unchanged inputs is a no-op.

Pipeline order: hand-edit `mapping.json` → `node scripts/tvfy/fetch-divisions.mjs` → `node
scripts/tvfy/fetch.mjs` → `node scripts/tvfy/apply.mjs` → `node scripts/validate.mjs`.
